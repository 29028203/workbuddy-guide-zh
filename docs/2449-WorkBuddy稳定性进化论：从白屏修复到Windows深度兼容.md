# WorkBuddy稳定性进化论：从白屏修复到Windows深度兼容

> 原文链接：[https://www.laoshoucun.com/workbuddyzl/2449](https://www.laoshoucun.com/workbuddyzl/2449)

<p>判断一个 AI 工具值不值得托付，别看发布会，看更新日志。把 WorkBuddy 从 5.3.7 到 5.3.13 六个版本的日志翻一遍，会看到一条贯穿始终的线索：Windows 冷启动闪退、macOS 文件系统性能滑坡，SSE 流式传输中文乱码，本地助理内存暴涨，全是稳定性修复。这些看着零碎，串起来是同一条产品主线：先保证能用，再谈好用。这条主线没什么性感的地方，但用过一堆花架子工具的人会懂它的分量。毕竟最败兴的体验从来不是 AI 答得不对，而是你把它当生产力使，它偏在下班前白屏给你看。</p>
<p>按时间捋一遍。5.3.7 一口气修了 26 项，重点收拾 Windows 冷启动闪退、任务执行中反复弹终端窗口，启动期网络代理超时堵住 UI 这些硬伤。5.3.8 修的是更隐蔽的一类：产物索引膨胀导致历史任务找不回来，用得久了历史数据越滚越大，系统变慢甚至回溯不了。这类问题比单个 bug 更伤信任，因为用户往往是在最需要翻旧账的时刻，才发现它坏了。</p>

<h2>断线之后，得自己接上</h2>
<p>先看一个容易被低估的修复：5.3.7 解决了端云同步断线后不自动重连。端云同步是 WorkBuddy 的核心能力，本地助理和云端服务之间的数据同步一旦断了又不自己接上，用户碰到的就是任务结果对不上、历史记录不一致。5.3.12 又往前走了一步，优化移动端连电脑在弱网、休眠恢复后的同步与续聊稳定性，顺手修了 IMA 连接器偶发掉线要重新授权的问题。方向始终如一：什么网络条件下都要拿到一致的体验。弱网不是用户的错，产品得自己兜住。</p>
<h2>Windows 的坑，藏在碎片化里</h2>
<p>Windows 兼容问题在修复清单里占了很大一块。5.3.11 修了非系统盘或中文路径下产物无法预览、下载或报 Access denied。5.3.12 修了 Windows 更新 loading 的关闭时机。5.3.7 修了启动期代理超时堵 UI 和冷启动闪退。单看哪个都不大，凑到一起就是在 Windows 上没法安心用。中文路径那条我特意记了一笔，很多人装机就是中文用户名，报错还看不懂为什么。</p>
<p>麻烦的根子在环境碎片化：系统版本各异、安装路径有系统盘和非系统盘之分，路径编码有英文有中文，代理配置和权限设置五花八门，每种组合都可能埋坑。对 <a href="https://www.laoshoucun.com/workbuddy" target="_blank" rel="noopener">WorkBuddy</a> 这种要在本地跑 AI 任务的工具，这条路难走但绕不开，毕竟 Windows 用户里，非系统盘，中文用户名，公司代理网络的占比一点都不小。</p>
<h2>出事时不慌，也是稳定性</h2>
<p>有一类更新不修任何性能问题，但同样重要。5.3.11 加了显示文件变更过程详情的开关，AI 执行任务时动了哪些文件，用户看得见，既是透明度，也是安全防护。5.3.12 加了对话出错时的检查网络快捷入口，网络异常一键跳诊断。这些功能解决的是用户出事时的慌张：知道发生了什么、知道去哪查，比干等一个修复版本踏实得多。</p>
<p>5.3.8 还修了预热进程首轮对话人设异常和登录状态不同步。预热进程是为省首次对话等待而提前拉起的进程，它的人设和登录状态不对，用户第一次对话就可能撞上&#8221;AI 不认识自己&#8221;的尴尬。这类修复说明团队开始在意首次体验，新用户的第一印象，常常直接决定他留不留。</p>
<h2>功能可以等版本，数据丢了没法重来</h2>
<p>所有 AI 工具都在比模型能力、功能数量，技能生态的时候，稳定性最容易被晾在一边。可现实是：用户选一个工具可能因为新功能，决定留不留的，通常是会不会突然崩、历史记录会不会丢，弱网下能不能用这些基本盘。</p>
<p>WorkBuddy 从 5.3.7 到 5.3.13 的持续投入，态度摆得很清楚：功能可以慢慢加，但已发布的功能必须稳。六个版本、上百条修复，每一条都在攒用户敢把活儿交给它的底气。等 <a href="https://www.laoshoucun.com/" target="_blank" rel="noopener">智能体</a> 工具真长成工作流程离不开的一环，稳定就不再只是技术指标，而是信任本身，到那一步，账才真正算得清。</p>
